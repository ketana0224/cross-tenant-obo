# 検証方法と証跡の限界

## 公開資料の位置付け

この公開セットは、既存の実機記録から結論と条件を抽出した**匿名化要約**。公開整理時に実機試験を再実行したものではない。

原本のログ、状態JSON、利用者の画面、管理APIの応答は非公開のまま保持する。公開資料だけで、第三者がすべての実行証跡を独立監査できる状態ではない。ID・秘密を含む原本を公開して根拠を補強しない。

## 証跡の種類

| 対象 | 確認した主な根拠 | 限界 |
| --- | --- | --- |
| D03：CS OBO／SSO | OBO・Invoker設定、本人所有SSO接続の新規生成と状態、利用者のidentity結果、一部のEntra認証成功ログ | 内部のトークン交換要求は直接採取していない。データ取得・権限外拒否は未検証 |
| D12・D17：Foundry MCP OBO | Blueprint入口、委任接続、本人に一致したnative実ツール出力。D12ではAPIログも確認 | 記録ごとに取得したログの範囲が異なる。全行にA2Aと同じreceipt形式があるわけではない |
| D09-M・D20-M：追加MCP OBO | 実ツール1回、完了状態、APIの検証済みtid・oid・actorログ、SP・本人限定同意 | 限定したidentity操作。複数発行元を無条件に信頼する構成ではない |
| D10・D13・D18・D21：MCP OAuth | 本人の下流用OAuth認可、同じ実行の再開、本人に一致した実MCP出力 | 接続再利用で画面が出ない場合がある。本人OBOとは別 |
| A07：MIによるAPI／MCP | 保存接続・アプリ権限・対応付け、実ツール出力、APIログ | 本人のデータ権限を下流へ継承した結果ではない |
| A10：MIによるAPI／MCP | 実ツール出力、保存接続、MI対応付け、アプリロール | リクエスト単位のAPI認証ログ照合は未実施。A07と同じログ証跡があるとは扱わない |
| T系列：A2Aの○ | 完了したnative call/output、期待するトークン識別情報・権限、同じ実行の受信側生成receiptと受信ログ | 専用identity agentの認証境界。業務データの認可やすべてのA2A実装は未検証 |

## 再検証する場合の手順

1. 対象行の配置・入口認証・下流アプリ登録・信頼発行元・方式を固定する。
2. 利用者／アプリの準備、環境利用権限、必要最小限の委任同意・アプリロールを確認する。
3. 本人実行と管理者準備を分離する。初回OBO／SSOを、通常OAuth接続の事前作成で代用しない。
4. 入口の `tid`・`oid`・`aud`・クライアント・`scp` を確認する。JWTの署名・期限検証を省略した診断だけで成功にはしない。
5. ネイティブツールを実行し、HTTPコードに加え、実行完了・実ツール出力・実際の主体を確認する。
6. OAuth許可要求があれば、本人のサインイン・必要なMFA／許可後に同じ実行を再開する。
7. 取得可能な受信ログと照合し、未取得の証跡は未取得として記録する。
8. 操作／データ認可を検証対象にする場合は、権限内成功と権限外拒否を別の試験として実施する。

Foundryのみの構成では、Power Platformの環境グループ所属とDataverse登録は「確認不要：使用しない」と独立して記録する。CSでは[利用者準備の順序](認証方式と成立条件.md)を省略しない。

### A2Aで採用した厳密な成功基準

- 期待するnative A2A callとoutputが完了し、同じcall IDに対応する。
- 受信側が生成したreceiptが、対象ケース・同じrun・期待する主体に一致する。
- 署名検証済みの受信側で、`tid`・`oid`・`aud` と委任スコープ／アプリロールを確認する。
- native実出力と受信側ログが一致し、最終応答まで完了する。
- エージェントが生成した文章、プロンプト内のidentity、過去runのreceiptを成功の証拠にしない。

## 失敗・未完了の分類

| 観測 | 記録すること | 断定してはいけないこと |
| --- | --- | --- |
| OAuth許可要求のみ | 本人操作待ち、下流実行未確認 | 個別OAuth成功／OBO成功 |
| モデル429・生成上限 | 実行阻害／最終応答未完了。受信済みなら別欄に記録 | トークン認証失敗 |
| 接続解決／ARAエラー | Foundry内の接続解決・トークン取得で停止 | 下流APIが401／403で拒否したとすること |
| MCP列挙／A2A SendMessageタイムアウト | 実行不成立、受信・発行元の確認状況 | 製品全体としてのOBO／別テナント非対応 |
| 匿名401 | 保護されたエンドポイントの負対照 | 本人OBOの成否 |
| Graph404 | 本文未取得。不存在と認可の切り分け状況 | テナント固有の拒否を直接証明したとすること |
| HTTP200・文書0件 | 期待する取得結果なし | 文書取得成功 |
| 接続・同意・ライセンスの保存 | 前提の設定済み状態 | 実ツール実行成功 |

## 未検証・一般化しない範囲

- Copilot StudioからのMCP／A2A、およびアプリ認証構成案の実機。
- A2AでのマルチテナントAPI追加構成、すべての同一／別テナントMI構成。
- 実Snowflake、標準Snowflakeコネクタ、業務データの網羅的な認可。
- すべての利用者・チャネル・ライセンス・リージョン・モデル容量への適用。
- 生の証跡を含む完全な再現用デプロイパッケージ。

プレビュー機能の仕様確認と実行結果は、検証時点に限定する。再検証時は[公式資料](公式資料と参照一覧.md)と実環境の設定を確認する。
