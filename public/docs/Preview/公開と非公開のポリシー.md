# 公開・非公開のポリシー

## フォルダーと公開許可リスト

| 場所 | 扱い |
| --- | --- |
| ルートREADME | 公開用の入口・資料のナビゲーション |
| ルート `.gitignore` | 公開対象の明示的なファイル許可リスト |
| `public/docs/` の許可されたMarkdown | 匿名化した結論・条件・マトリクス・公式参照 |
| `public/examples/` の許可されたREADME／JSON | 実環境の値を含まない概念テンプレート |
| `private/` | 今後の非公開設定・証跡・作業成果物、既存資産へのローカル索引 |
| 既存のその他の場所 | 原本・コード・環境設定を移動／上書きせず保持し、既定でGit対象外 |

publicに置くだけでは公開対象にならない。新しいファイルを公開する場合は、内容確認後に `.gitignore` の許可リストへ明示的に追加する。

既存資産を動かさない制約のため、従来の非公開フォルダーはルートに残している。privateへの集約は**今後作る非公開成果物**に適用する。既存ファイルの移動・削除はこの整理では行わない。

## 公開する情報

- 認証／認可の成立条件と、成功した構成の範囲。
- 入口認証・ホスト・登録先・信頼発行元を区別した匿名H/Rモデル。
- 接続方式ごとの実機成功、実行不成立、仕様確認、未検証の区別。
- 原資料番号と公開ID（D／A／T）の対応。
- 個人やリソースを特定できない検証日・観測の要約。
- 公式ドキュメントの参照、プレースホルダーだけの設定例。

## 公開しない情報

- 元のExcel・画面・詳細検証記録・未選別のソース／IaC／実行スクリプト。
- 実Tenant ID、UPN、個人名、Object ID、App ID、Subscription ID、環境／プロジェクト／接続／文書ID。
- 実API・Foundry・SharePointのURL、実リソース名、リビジョン、相関／run／receipt ID。
- 秘密、証明書、秘密鍵、トークン、認可コード、OAuth同意URL、セッション情報。
- `.env`、クラウド認証キャッシュ、ローカル状態、受信ログ、ビルド成果物、個人設定。

Tenant IDやApp IDが秘密鍵でなくても、今回の公開セットでは環境を特定する情報として除外する。

## 公開前の確認

以下は確認手順であり、この資料を作成しただけでGitHubへの公開が完了するわけではない。

```powershell
git --no-pager status --short --untracked-files=all
git ls-files
git ls-files --others --exclude-standard
git check-ignore -v -- env/.env private/README.md validate4/state.json
git --no-pager diff -- README.md
git --no-pager diff --cached --stat
git --no-pager diff --cached
git --no-pager log --all --name-only --format=oneline
```

チェックすること：

1. 未追跡の公開候補がREADME・`.gitignore`・許可されたpublicファイルに限定されていること。
2. publicのJSONがプレースホルダーだけで、現実のID・秘密・同意URLを含まないこと。
3. 公開Markdownのローカルリンクが公開セット内で完結し、非公開原本へのリンクでないこと。
4. 既存資料をそのままコピーした場合の実名・URL・ログ・古い番号／判定が混入していないこと。
5. ○の方式・操作・証跡範囲と、×／—の留保が各マトリクスで整合すること。
6. ステージ済み内容とすべての公開予定ブランチ・タグ・履歴を確認すること。
7. 公開する資料の権利とライセンスを決めること。この整理ではライセンスを新たに付与していない。

**`.gitignore` は既に追跡したファイルを除外しない。Git履歴やリモートに既に存在する情報も消さない。** 除外ルールに反する追跡ファイルが見つかった場合は、公開を止めて個別に扱いを決める。履歴改変や追跡解除を自動実行しない。

### 今回確認したGit参照

整理時点の通常ブランチ `main` と `origin/main` の履歴は、ルートREADMEのみの初期コミットだった。一方、ローカルの `refs/agents/` 配下には、従来のコード・資料を含むチェックポイント参照がある。

**`git push --mirror` や全参照の明示的な送信は行わない。** 公開時は内容を確認した公開用ブランチだけを明示して送る。作業用リポジトリ全体や `.git` を公開アーカイブへ含めない。今回の整理ではチェックポイントや履歴を削除・改変していない。

この観測は整理時点の状態であり、今後のコミット・タグ・参照追加後にも同じ状態とは限らない。公開直前に再確認する。

`git add -f` は除外を回避するため、非公開資産には使用しない。ignoreはファイルへのアクセス権限ではない。privateの秘密は通常の安全な資格情報ストア等で管理する。

## 更新時のルール

- 非公開原本を保持し、新しい検証結果をpublicへ匿名化して反映する。
- 原条件と変更後条件、仕様確認と実機観測を分ける。
- テストの成功件数を、実機認証・認可の成功件数として扱わない。
- 実際の資格情報をテンプレートに埋めてから再匿名化する運用を避ける。
- 新しいデータ認可／チャネル／製品構成は、実機証跡が確認できるまで未検証とする。
