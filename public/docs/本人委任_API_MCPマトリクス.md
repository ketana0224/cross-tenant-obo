# 本人委任・API／MCPのマトリクス

原資料の22構成に `D` を付けて匿名化した。D番号は[アプリ認証のA番号](アプリ認証マトリクス.md)・[A2AのT番号](A2A認証マトリクス.md)とは別系列。

H/Rは[構成定義](構成と用語.md)。下流の「発行元」は、下流が受け入れる認証テナントを示す。○は**その行の方式での成功**であり、個別OAuth／MIの○を本人OBOの○とはしない。

- **○**：記載した操作と方式で実機成功。
- **×**：実行不成立、または明記した仕様上の非サポート。仕様判定は実機の実行失敗と区別する。
- **—**：未検証・仕様確認のみ。条件候補の記載は実証ではない。
- データは主に合成identity。証跡の強さ・未検証範囲は[検証方法](検証方法と限界.md)を参照。

## 条件変更後のMCP追加構成

元条件のAPIは変更せず、専用APIを追加して確認した。成功はidentity操作に限定する。

| ID | 元条件からの変更 | 下流が受け入れた本人 | 結果 |
| --- | --- | --- | --- |
| D09-M | H登録APIをマルチテナント化、R側にAPI SP・本人限定委任同意、R発行トークンの検証／認可 | R発行のRゲスト本人 | ○ 本人OBO。実MCP出力1件・APIの検証済み本人／actorログを確認。2026-11-05 |
| D20-M | R登録APIをマルチテナント化、H側にAPI SP・本人限定委任同意、H発行トークンの検証／認可 | H発行のH本人 | ○ 本人OBO。実MCP出力1件・APIの検証済み本人／actorログを確認。2026-11-05 |

両方とも入口Blueprintは単一テナント。下流APIの登録先と発行元を分けた結果であり、入口の本人を別テナントの本人へ変換した結果ではない。**マルチテナント化だけで成功したとも、すべてのテナントを許可したとも扱わない。**

A2A版の同じ追加構成は未検証。元のSharePointをA2Aへ置換した結果も、この表のSharePointの結果を置き換えない。
