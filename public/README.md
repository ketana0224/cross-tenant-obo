# マルチテナントのエージェント連携：公開資料

Microsoft Foundryを中心に、本人OBOとアプリ認証・マネージドID（MI）の基本、クロステナント構成、検証結果をまとめる。

**M365＝利用者ユーザーIDが登録されているテナント、Azure＝それとは別のAzureリソース側テナント**。

## 基本

| 資料 | 内容 |
| --- | --- |
| [OBOの基本](docs/OBOの基本.md) | 本人に代わって下流サービスへアクセスする仕組み、トークン交換、委任権限・同意 |
| [アプリ認証とMIの基本](docs/アプリ認証とMIの基本.md) | アプリ自身でアクセスする仕組み、MI、権限付与、本人OBOとの違い |

## クロステナント構成

M365の利用者が、別のAzureテナントに配置されたFoundryを利用する構成を、Azure側へのゲスト登録の有無と下流の認証方式で分ける。

| 認証方式 | ゲストユーザー | 非ゲストユーザー |
| --- | --- | --- |
| 本人OBO | [クロステナントOBO-ゲストユーザー](docs/クロステナントOBO-ゲストユーザー.md) | [クロステナントOBO-非ゲストユーザー](docs/クロステナントOBO-非ゲストユーザー.md) |
| アプリ認証・MI | [クロステナントアプリ認証とMI-ゲストユーザー](docs/クロステナントアプリ認証とMI-ゲストユーザー.md) | [クロステナントアプリ認証とMI-非ゲストユーザー](docs/クロステナントアプリ認証とMI-非ゲストユーザー.md) |

非ゲスト版は、Azure側に本人を登録せず、Azure認証の入口へ本人が直接アクセスする前提での制約を説明する。非ゲストのすべての構成が不成立という意味ではない。

## 検証結果

[検証結果統合マトリクス](docs/検証結果統合マトリクス.md)

MCP・A2A・SharePoint・入口認証・HTTP／OpenAPI・カスタムコネクタの結果を、製品・配置・認証方式ごとに掲載する。

- Foundry(Azure)・Foundry(M365)の結果を分け、成功・不成立・仕様上の非対応・未検証を区別する。
- Copilot Studio・コネクタ単体の表は参考情報として掲載する。
- 「結果・条件・確認範囲」「検証日・出典」は検証時のメモであり、参考情報としてのみ使用する。

検証期間：**2026-11-01〜2026-11-09**。結果は検証時点のものであり、現在の設定・資格情報の有効性や、すべての構成での動作を保証しない。

## 読む順番

1. 「OBOの基本」「アプリ認証とMIの基本」で、本人委任とアプリ認証の違いを確認する。
2. 対象の認証方式とゲスト登録の有無に応じて、クロステナント構成を読む。
3. 「検証結果統合マトリクス」で、対象の製品・配置・認証方式の結果と条件を確認する。
